# Fungal Taxonomic Classification and Parsing Pipeline

This repository documents a high-performance taxonomic classification pipeline using Kraken2 and Bracken, followed by custom parsing scripts to generate abundance matrices for downstream Jupyter Notebook analyses.

## System Requirements & Environment

* **OS:** Ubuntu 24.04.3 LTS x86-64
* **CPU:** AMD EPYC 9374F (128 threads) @ 3.850GHz
* **RAM:** 512 GB (Crucial for in-RAM database loading via `vmtouch`)
* **Dependencies:** `kraken2`, `bracken`, `seqfu`, `vmtouch`, `parallel`, Python (`ete4`).

---

## Part 1: Database Construction & Classification

### 1. Database Setup
The classification relies on a custom database combining RefSeq Fungi and JGI MycoCosm genomes.
* **Download Taxonomy:** `conda run -n kraken2 k2 download-taxonomy --db $DB_NAME`
* **Add Genomes:** `kraken2-build --add-to-library fungi_refseq_JGI.fa --db $DB_NAME`
* **Build DB:** `kraken2-build --build --db $DB_NAME --threads 40`
* **RAM Optimization:** The database is loaded into `/dev/shm` using `vmtouch -vt /dev/shm/db/*.k2d` to maximize I/O performance during classification.

### 2. Core Script: `k2_b_classification.sh`
**Description:** Automates sequence quality checks, interleaving, Kraken2 taxonomic assignment, and Bracken abundance estimation. 

**Usage:**
```bash
./k2_b_classification.sh <DB_NAME> <FASTQ_DIR> <OUT_DIR> <TMP_DIR>
```

* **Inputs:**
  * `$1`: Kraken2/Bracken database path.
  * `$2`: Directory containing input `.fastq.gz` files.
  * `$3`: Output directory for reports and logs.
  * `$4`: Temporary directory for interleaving files.
* **Outputs:** * `<ID>.k2.report` (Kraken2 taxonomic report)
  * `<ID>.bracken.S.report` (Bracken species-level abundance report)
  * `<ID>.log` (Processing log)

## Part 2: Post-Classification Parsing

The parsing step is divided into two distinct subdirectories based on the dataset structure: **EMP** (Earth Microbiome Project) and **food**.

### Earth Microbiome Project (EMP)
The EMP dataset requires handling cases where multiple sequencing runs map to a single sample ID.

#### Script: `reads_file.sh`
**Description:** Extracts read statistics (total, classified, unclassified) from Kraken2 logs, accounting for many-to-one sample mappings.

**Usage:**
```bash
./reads_file.sh <LOGS_DIR> <MAPPING_FILE> <OUTPUT_FILE>
```

* **Inputs:**
  * `LOGS_DIR`: Path to the `.log` files generated by Kraken2.
  * `MAPPING_FILE`: TSV linking run IDs to actual sample IDs.
* **Output:** `reads_earth_microbiomes_k2_B.tsv` 
  *(Format: ID, sample_name, total, classified, unclassified)*

#### Script: `parsing_kraken.py`
**Description:** Parses the Bracken `.report` files to build a single abundance matrix. It uses the `ete4` library to retrieve the full taxonomic lineage, specifically isolating the `subphylum` rank.

**Usage:** Executed directly via Python (paths are set internally).

* **Inputs:** * The `reads_earth_microbiomes_k2_B.tsv` mapping file.
  * The folder containing Bracken `.report` files.
* **Output:** `kraken_absolute_isyeast_subphylum.tsv`

*(Note: This output is subsequently processed by `yeast_taxa_checker_v5.py` to append the `isyeast` boolean column, yielding the final `kraken_absolute_isyeast_final.tsv`)*

---

### Food Microbiomes
The Food dataset has a strict 1:1 mapping between sequencing runs and sample IDs, and utilizes a dedicated metadata file (`cFMD_metadata.tsv`) for downstream filtering.

#### Script: `reads_file.sh`
**Description:** Extracts read statistics directly from logs without complex mapping logic.

**Usage:**
```bash
./reads_file.sh <LOGS_DIR> <OUTPUT_FILE>
```

* **Inputs:**
  * `LOGS_DIR`: Path to the Kraken2 `.log` files.
* **Output:** `reads_food_microbiomes_k2_B.tsv`
  *(Format: ID, total, classified, unclassified)*

#### Script: `parsing_kraken_food.py`
**Description:** Similar to the EMP counterpart, this script compiles Bracken reports into a full abundance matrix with subphylum-level taxonomy via `ete4`, adapted for 1:1 sample mapping.

**Usage:** Executed directly via Python (paths are set internally).

* **Inputs:**
  * The `reads_food_microbiomes_k2_B.tsv` file.
  * The folder containing Bracken `.report` files.
* **Output:** `kraken_absolute_isyeast_subphylum.tsv`

*(Note: As with EMP, this matrix goes through `yeast_taxa_checker_v5.py` to produce the final `kraken_absolute_isyeast_final.tsv` used in Jupyter Notebooks).*

## Part 3: EukDetect Taxonomic Classification and Parsing

In addition to Kraken2, eukaryotic metagenomic profiling was conducted using **EukDetect v1.3** (*Note: v2.0.0 is currently available*).

### 1. Configuration and Execution (`create_configfile.sh`)
EukDetect relies on specific YAML configuration files based on read length and sequencing layout (paired-end vs single-end). We developed `create_configfile.sh` to automate the generation of these files, dynamically skipping samples with fewer than 10,000 reads to ensure high-confidence outputs.

**Usage:**
```bash
./create_configfile.sh <LIST_FILE> <FASTQ_DIR> [OUTPUT_DIR]
```

Once configured, the classification was executed allocating 20 cores per run:
```bash
eukdetect --mode runall --configfile <YOUR_CONFIG.YML> --cores 20
```
This generates a table for each sample named `<ID>_filtered_hits_eukfrac.txt`, containing the taxonomic lineage and eukaryotic read fractions.

### Earth Microbiome Project (EMP)

The EMP EukDetect outputs are compiled, metadata is injected, and the taxonomy is standardized in a multi-step parsing process.

#### Script 1: `merged_files.py`
**Description:** Compiles all individual EukDetect hit tables into a single dataset, explicitly keeping only the `species` rank. It injects the `sample_name` and EMPO categories based on provided metadata mappings.

**Usage:**
```bash
python3 merged_files.py <EUKDETECT_OUT_DIR> <METADATA_FILE> <TAXONOMY_FILE> -o earth_microbiomes_eukdetect_results.tsv
```

#### Script 2: `merge_all_final.py`
**Description:** Merges the previously generated EukDetect results with read length data and standardizes missing metadata columns, dropping unnecessary tracking columns generated by EukDetect.

**Usage:**
```bash
python3 merge_all_final.py <FILE_A> <FILE_B> <READS_LENGTH_TSV> <SAMPLES_TSV> <OUTPUT_TSV>
```

#### Script 3: `subphylum_taxo.py` & Yeast Annotation
**Description:** Utilizes the `ete4` library to retrieve the `subphylum` rank for each valid TaxID identified by EukDetect. Afterward, `yeast_taxa_checker_v5.py` is applied to append the `isyeast` boolean flag.

**Usage:** ```bash
python3 subphylum_taxo.py <INPUT_TSV> <OUTPUT_TSV>
# Followed by:
python3 yeast_taxa_checker_v5.py <INPUT_TSV> <FINAL_TSV>
```

**Final Output Example:** earth_microbiomes_eukdetect_subphylum.tsv

### Food Microbiomes

The Food microbiomes dataset utilizes a distinct parsing script to inject food-specific metadata (macrocategories, types, and subtypes).

#### Script 1: `create_lineage_file.sh`
**Description:** Extracts species-level hits from EukDetect output files and maps them against the `cFMD_metadata.tsv` categories file, structuring the output to include food taxonomy levels.

**Usage:**
```bash
./create_lineage_file.sh <EUKDETECT_OUT_DIR> <CATEGORIES_FILE> <OUTPUT_FILE>
```

#### Script 2: `subphylum_taxo.py` & Yeast Annotation
**Description:** Identical to the EMP workflow, this script uses `ete4` to resolve the `subphylum` lineage for food-associated taxa. It handles missing values robustly and is followed by the `yeast_taxa_checker_v5.py` tool.

**Usage:** Executed directly via Python.

**Final Output Example:** `food_microbiomes_eukdetect_subphylum.tsv`

## Data Visualization and Analysis

* **`plots/` directory:** Contains dedicated, lightweight Python scripts and their corresponding `.tsv` input files used exclusively to generate the metagenomic figures presented in the study.
* **Jupyter Notebooks:** Located within the respective `EMP/` and `food/` subdirectories. These notebooks contain the code used to process the final matrices documented above, performing statistical analyses and generating the datasets used by the scripts in the `plots/` directory.
